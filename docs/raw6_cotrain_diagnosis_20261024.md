# 8005 Cotraining 真机孔口失败：当前证据与待验证原因

用户反馈：8005 原始六维力 Cotraining 能到孔口但无法完成插入；较早测试的纯真机
模型基本可以成功，使用的客户端、相机与控制参数相同。纯真机成功记录不是本次
同一天、同一初始条件下的 A/B，尚不能排除场景、力零点或硬件状态的时间变化。

## 可以确认的内容

1. 对应配置 `pi0_lora_user_single_arm_ee_wrench_cotrain_aligned_50_50` 使用真机和
   `local/tavla_single_arm_sim_aligned` 两个数据源，采样权重为 0.5/0.5。
   仿真源后三维力矩为零，真机保留完整六维力。依据为
   `scripts/run_tavla_raw6_aligned_cotrain.sh` 与 `src/openpi/training/config.py`。
2. 对应训练入口使用 `pi0_base/params` 初始化，训练 30,000 步、global batch 8；
   入口没有从用户曾成功的纯真机 checkpoint 初始化的参数。配置不能替代历史
   训练命令的完整证明，本次迁移包未包含原实验训练日志和完整运行 manifest。
3. 推理从 checkpoint 自带的 `assets/norm_stats.json` 加载归一化统计。
   启动时先尝试读取训练资产路径产生的 warning，不等于实际推理缺少归一化。
   此次部署的模型恢复、WebSocket 推理、动作形状和有限值检查通过。
4. 本机可用纯真机 baseline `first_lora_ee_wrench/29999` 和 `ee_wrench_ckpt10k/29999`
   的统计彼此相同；它们不一定是用户以前真机测试的那份权重。

本机纯真机 baseline 与 8005 checkpoint 的力统计（均值 / 标准差）：

| 通道 | 本机纯真机 baseline | 8005 Cotraining |
| --- | --- | --- |
| Fx | -2.5423 / 1.6714 | -1.2501 / 1.7603 |
| Fy | 0.4312 / 1.2777 | 0.1945 / 0.9553 |
| Fz | -1.0318 / 2.8150 | -0.7782 / 2.4888 |
| Tx | -1.1241 / 1.5958 | -0.5603 / 1.2551 |
| Ty | -1.2457 / 1.4829 | -0.6334 / 1.1835 |
| Tz | 0.2434 / 0.1926 | 0.1223 / 0.1838 |

力统计变化是混合数据训练的结果，本身不能证明归一化错误。不要直接把纯真机
统计替换到 Cotraining checkpoint：模型已按自己的统计训练，这会再改变输入输出映射。

## 高优先级假设

- **接触阶段负迁移**：一半训练样本没有真实的力矩变化，仿真力与真机接触反馈的
  对应关系也未由闭环成功率证明一致。共享策略可能削弱原本有用的接触纠偏响应。
  这与“可到孔口但插不进”的现象相容，仍需要同输入动作对比与当前场景 A/B 验证。
- **初始化与真机监督预算变化**：当前入口不是以成功的纯真机策略为起点继续微调。
  固定总采样数时，50:50 会减少真机样本曝光；应按实际 baseline 的 batch、步数和
  初始化对齐比较，不能仅以两者都训练 30,000 步判断训练预算相同。
- **当前场景/力定义变化**：即使客户端没改，较早成功与当前失败也可能受到相机、
  夹持位姿、孔/工件位置、力零点、力矩参考点或控制延迟变化影响。

## 当前采样实现的覆盖风险

`WeightedMixtureDataset` 在构造时用固定 seed 42 生成有放回帧索引，之后每个 epoch
只重新迭代同一组索引；shuffle 仅改变它们的顺序。当前配置默认
`dataset_sampling_mode="with_replacement"`。

按入口检查的每域 7,188 帧、50:50 配比复现该索引生成过程：

- 真机：4,559 个不同观测起始帧，占 63.43%。
- 仿真：4,510 个不同观测起始帧，占 62.74%。

这说明当前代码有固定重复采样、未覆盖部分观测起始帧的风险。它不等于这些帧
从未作为未来 action 标签出现，也不能单独证明此次孔口失败的原因。只有原训练
确实使用这一实现时，该覆盖结论才适用于迁移的 checkpoint。本次只诊断，未修改
数据加载器、训练配置或 8005 权重。

## 最小验证顺序

1. 当前场景重测原纯真机 checkpoint 与 8005，固定客户端、初始状态和动作执行方式。
2. 保存孔口前后同步的两路 RGB、state、原始 wrench、采集时间、模型 actions、
   实际选用 action 索引以及控制器执行后的状态。
3. 离线向两个模型重放同一观测；比较接触时纠偏方向、下一步位移、夹爪目标，
   并检查动作仍按绝对关节角执行。离线误差不能替代闭环成功率。
4. 若确认混合训练退化，再分别比较真实模型初始化、较低仿真占比、采样覆盖修正，
   每次固定其余条件。8001 的服务端 encoder 接口改动不构成 8005 性能修复。
